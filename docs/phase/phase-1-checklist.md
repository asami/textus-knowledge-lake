# Phase 1 — Project-local Acceptance Checklist

Authority: [Phase 1](phase-1.md). All items below concern TKL-local delivery; unchecked items are pending and are not evidence of implementation.

- [ ] Provider-neutral Resource / Evidence / Context / Run / PreparedMaterial / Proposal contracts and versioned JSON are specified.
- [ ] Representative local fixture flow produces persisted PreparedMaterial and an evidence-grounded RawCandidateProposal.
- [ ] JSON round-trip and Markdown projection are verified without external source access.
- [ ] Stable identities, distinct revisions, immutable historical inputs and retention/unknown-provenance semantics are verified.
- [ ] Local persistence update conflicts and partial failures have observable, tested outcomes; Drive guarantees remain explicitly unverified.
- [ ] TKL proposal identity, result correlation, rejection/conflict and timeout/retry handling are verified against a local boundary fixture.
- [ ] Supported native CML models the TKL-owned Use Case / Workflow; missing shared capabilities are recorded without local substitutes.
- [ ] A repository-owned validation command runs without another source checkout, running external applications or live credentials.
- [ ] README / notes / CML / journal agree on ownership, scope and actual assurance.
- [ ] Independent review and required local validation evidence are recorded.
- [ ] Integration register statuses and unresolved external guarantees are reconciled.
- [ ] Closing proposals include owners, exact TKL contract/source versions, sample payloads, acceptance examples, open questions and follow-up work.

Actual TKW receipt/Admission, TEAI delivery, KnowledgeHub changes, BoK publication and live Workspace verification are external follow-up proposals, not checklist completion prerequisites.
