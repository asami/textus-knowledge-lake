The assessment's [controlled transport evidence](../../../notes/google-drive-capability-assessment.md#controlled-transport-evidence--2026-10-03) records the observed status, body and control boundaries. HTTP 200 preserved selected valid Japanese/emoji/newline and empty text; binary `Bag` retained original bytes. 401/403/404 preserved code/body and case-insensitive `Retry-After`, while 409/429/503 and bodyless 204 collapsed to 500, losing physical status information. 201 retained its code but failed the narrow `isSuccess` helper, which recognizes only 200. Malformed `text/plain` UTF-8 bytes `C3 28` decoded to U+FFFD and an opening parenthesis, so the String or re-encoded bytes cannot prove strict decoding or recover the invalid original bytes. POST JSON/headers, byte bounds, disabled redirect and network policy were characterized; a response closed before headers raised `IOException` and may involve multiple physical attempts, without asserting an exact retry count or provider outcome.
